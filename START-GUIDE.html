Operating guide

Codex

Offline knowledge corpus: 13 SQLite codexes behind one warm search daemon. Open this file and get running in under a minute. No internet, no server, no setup beyond a Python environment.

01Current status

The daemon answers on 127.0.0.1:8765. Everything else is a client of it: the web UI, scripts, tools. Check whether it is running:

bash scripts/linux/status.sh
curl http://127.0.0.1:8765/api/health

If you have not started it yet, not running / no response is the expected answer, not an error — continue to Quick start below.

A healthy answer lists every codex with its document count. A failed curl means the daemon is not running (or is still loading, see Troubleshooting).

02Quick start

One command starts the daemon, waits until it is healthy, and opens the web UI in your browser. Safe to run twice: it detects a running daemon and exits. First, a one-time Python environment (the start script uses .venv when present; without it, it falls back to the system interpreter, which lacks the dependencies and fails after a long wait):

python3 -m venv .venv && .venv/bin/pip install libzim selectolax zstandard numpy Pillow pytest
bash scripts/linux/start.sh
Opens the UI at http://127.0.0.1:8765/ when ready. Wikipedia takes 20 to 40 s to load; the script waits for the health endpoint, so a slow start is normal. Set CODEX_NO_BROWSER=1 to skip the browser.
bash scripts/macos/start.sh
Same behavior as Linux, opens via open. Run from the project root or anywhere: the script resolves its own location.
powershell -ExecutionPolicy Bypass -File scripts\windows\start.ps1
Uses .venv\Scripts\python.exe when present, else the py launcher. One daemon shows as two PIDs in Task Manager: that is the venv redirector stub plus the real interpreter, not a duplicate.

Manual start (development) dev

python app/codexd.py

Defaults come from the project layout itself: loads every data/*.codex.db plus data/art.db. Works from any directory. Add --port N, --host 0.0.0.0 (LAN, no auth: trusted networks only) or --codex PATH to narrow the set.

03Stop

Graceful SIGTERM first, then SIGKILL only if it ignores the request. Safe to run when nothing is running.

bash scripts/linux/stop.sh
bash scripts/macos/stop.sh
powershell -ExecutionPolicy Bypass -File scripts\windows\stop.ps1
Matches on the command line (*codexd.py*), never on the executable name: an earlier version filtered on pythonw.exe alone and matched neither of the two PIDs.

07Web UI

Single-file app served by the daemon itself. Nothing to install, nothing to build.

http://127.0.0.1:8765/
  • Keys: ↑/↓ move, Enter opens the reader, Tab toggles quick/deep search, Esc goes back.
  • Queries are debounced at 120 ms and never run below two characters.
  • Prefix search only expands the last term, from 3 characters up (bat works, ba is refused: measured 10x slower).
  • Assets live in app/web/ and are read per request: editing HTML/CSS needs only a reload; Python changes need a daemon restart.

09Development commands

Run from the project root with your environment's Python (see README, Install). Read-only by default.

python app/codexctl.py info data/ifixit.codex.db
python app/codexctl.py search data/ifixit.codex.db "iphone battery" -n 5
python app/tools/calibrate.py archive.zim
python app/tools/gaps.py data/ifixit.codex.db
python app/tools/stats.py data/ifixit.codex.db

Rebuilding (long-running, writes data) danger

python app/codexctl.py build archive.zim --out data --workers 10 --scratch _work/scratch

Wikipedia-class builds run hours and a checkpoint survives every 50k documents or 2 minutes. Keep --scratch on a different volume from the source archive. Stop the daemon first if the target codex is loaded, and restart it after: it globs data/*.codex.db once at startup.

python app/tools/rebuild_deep.py data/ifixit.codex.db
python app/tools/art_manifest.py && python app/tools/art_build.py

The art pipeline fetches from Wikimedia (rate-limited) and rewrites data/art.db. Never delete _work/art_cache/: a stopped run resumes for free from the cache.

10Tests

The suite pins search ranking, zstd round-trips, referential integrity, prefix gating, hygiene rules and the portable layout. Run after touching codex/search.py or the ranking blend.

python -m pytest app/tests/ -q

Works from any directory: the suite finds data/ through the same path module the app uses. 138 passing on Linux as of 2026-09-25. The daemon boot test opens a scratch port (8877) and stops itself.

11Common troubleshooting

  • curl fails right after starting. Not a crash: Wikipedia takes 20 to 40 s to load. The start script waits and reports. Watch _work/logs/codexd.out.log for the per-codex load lines.
  • Newly built codex is not in the list. The daemon globs once at startup. Restart it.
  • Two codexd PIDs on Windows. Normal: the venv redirector stub spawns the real interpreter. Stop scripts match the command line, not the process name.
  • "no Python found". Create .venv per README Install, or point CODEX_PYTHON at an interpreter that has the dependencies.
  • Search feels dead on short input. Prefix expansion starts at 3 characters by measured design: "ba"* cost 1,894 ms against 191 ms for "bat"*.
  • Port 8765 already in use. Something else owns it. Find it (Linux/macOS: ss -tlnp | grep 8765), stop it, or run the daemon on another port with CODEX_PORT.
  • A codex fails to load. The daemon logs the error and continues with the rest. Check _work/logs/codexd.err.log, and verify the file with PRAGMA quick_check in any SQLite tool.
  • Art images missing. The daemon degrades gracefully: no art.db, no pictures, nothing else notices. Point CODEX_ART_DB at the right file if you moved it.
